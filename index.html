02 / 08 · THE FLAW

ข้อบกพร่องร้ายแรงของ AI: Drift vs Forgetting

ทำไมระบบตรวจจับในปัจจุบันถึงล้มเหลวเมื่อเผชิญหน้ากับกลุ่มมิจฉาชีพที่ใช้ AI?
🦠

ปัญหาที่ 1: Concept Drift
มิจฉาชีพเปลี่ยนกลยุทธ์ตลอดเวลา

คนร้ายใช้ LLMs เพื่อสร้างข้อความหลบเลี่ยงรูปแบบใหม่ (Zero-Day Evasions) หากเราใช้ Static Model (โมเดลตายตัว) ระบบจะล้มเหลวทันทีเมื่อเจอบริบทที่เปลี่ยนไป

🧠

ปัญหาที่ 2: Catastrophic Forgetting
AI เรียนรู้สิ่งใหม่ แต่ลืมสิ่งเก่า

หากเราปล่อยให้ AI เรียนรู้แบบ Naive Continual Learning โมเดลจะจับสแกมใหม่ได้ แต่จะเกิดอาการ "ความจำเสื่อม" ลืมวิธีป้องกันสแกมรูปแบบเก่าไปอย่างสิ้นเชิง ทำให้เกิด False Positives มหาศาล

03 / 08 · THE CATALYST

พลังของ AI ยุคใหม่: เปลี่ยนกระบวนทัศน์การป้องกัน

งานวิจัยนี้เป็นไปได้ในปัจจุบัน เพราะเราดึงศักยภาพสูงสุดของเทคโนโลยี AI ล่าสุดมาใช้งาน (Modern AI Superpowers)
1. Edge SLMs

เราไม่จำเป็นต้องส่งข้อมูลส่วนตัวไปประมวลผลบน Cloud อีกต่อไป ด้วย Small Language Models เราสามารถรันโมเดลภาษาไทยบนมือถือผู้ใช้โดยตรง (OpenVINO) การันตี Latency < 300ms และความเป็นส่วนตัว 100%

2. PEFT (LoRA)

การอัปเดต AI ไม่จำเป็นต้องใช้ Supercomputer หรือเวลาหลายสัปดาห์ Parameter-Efficient Fine-Tuning ช่วยให้โมเดลปรับตัวรับมือสแกมใหม่ได้ในเวลาเสี้ยวนาที โดยปรับน้ำหนักเพียงส่วนเล็กๆ ของเครือข่ายประสาทเทียม

3. LLM Red-Teaming

ไม่ต้องรอให้มีเหยื่อก่อนถึงจะป้องกันได้ เราใช้ AI (HexStrike) สวมบทบาทเป็นมิจฉาชีพ เพื่อ Generate Synthetic Attacks โจมตีและทดสอบความแข็งแกร่งของระบบเราเองแบบเชิงรุก (Proactive Defense)

04 / 08 · ENTER THE HERO

Aegis V10: ฮีโร่ที่ปกป้องและวิวัฒนาการ

Aegis ไม่ใช่แค่ Text Classifier แต่เป็น Safety-Gated Continual Adaptation System ที่มาพร้อม 2 อาวุธหลักทางคณิตศาสตร์
👁️ อาวุธที่ 1: SEW-BFAR (อัลกอริทึมมองภาพรวม)

Aegis ไม่ประเมินข้อความแบบแยกส่วน แต่มองเห็น "ภาพรวม" ของทั้งบทสนทนา

ใช้อัลกอริทึม Sequential Probability Ratio Test (SPRT) คำนวณความเสี่ยงสะสม (Cumulative Risk) เมื่อมิจฉาชีพสร้างความกดดันถึงจุดวิกฤต Aegis จะแทรกแซงทันทีด้วย Bayesian UI ก่อนที่เงินจะออกจากบัญชี

🛡️ อาวุธที่ 2: CSU (ประตูล็อกความปลอดภัย 6 ชั้น)

เมื่อ Aegis เรียนรู้สแกมรูปแบบใหม่ โมเดลเวอร์ชันใหม่จะต้องผ่าน Certified Safe Update (CSU) Protocol

นี่คือด่านทดสอบสถิติ 6 มิติ เช่น ห้ามลืมข้อมูลเก่าเด็ดขาด, FPR ต้องไม่เพิ่มขึ้น หากโมเดลใหม่สอบตกแม้แต่ข้อเดียว จะถูกทำลายทิ้งทันที! การันตีด้วย Monotonic Safety Theorem (มีแต่ฉลาดขึ้น ไม่มีวันแย่ลง)

07 / 08 · EVALUATION METRICS

มาตรวัดความสำเร็จ (The Evaluation Rubric)

การทดสอบ Aegis V10 ต้องมีเกณฑ์ชี้วัดทางคณิตศาสตร์ที่ชัดเจน ว่าแบบไหนคือ "ผ่าน" (ใช้งานได้จริง) และแบบไหนคือ "ล้มเหลว"
มาตรวัด (Metric)เกณฑ์ที่ผ่าน (Good / Pass)จุดล้มเหลว (Fail)
1. Sequential Lead Time
เวลาแจ้งเตือนก่อนความเสียหาย		 > 1 ขั้นตอน
เตือนก่อนที่เหยื่อจะกดยืนยันโอนเงิน หรือก่อนกรอกข้อมูลสำคัญ (ทันเวลา)		 <= 0 ขั้นตอน
เตือนหลังจากโอนเงินไปแล้ว หรือเตือนพร่ำเพรื่อตั้งแต่ทักทาย (Alert Fatigue)
2. Backward Transfer (BWT)
มาตรวัดการลืมข้อมูลเก่า		 BWT ≥ 0
โมเดลจำวิธีป้องกันสแกมรูปแบบเก่าได้ 100% (ไม่มี Catastrophic Forgetting)		 BWT < 0
ลืมข้อมูลเก่า จับสแกมใหม่ได้แต่สแกมเก่าหลุดเข้ามาในระบบ
3. Attack Success Rate
ความแข็งแกร่ง (Robustness)		 ASR < 1%
ต้านทานข้อความหลบเลี่ยง (Zero-Day Evasions) จาก HexStrike ได้เกือบสมบูรณ์		 ASR > 5%
คนร้ายแค่พิมพ์เว้นวรรค หรือเปลี่ยนคำสะกดนิดเดียว ก็ทะลุระบบได้
4. False Positive Rate
อัตราการเตือนผิดพลาด		 FPR ≤ 0.1%
แชทปกติ 1,000 ครั้ง เตือนผิดไม่เกิน 1 ครั้ง (ผู้ใช้ยอมรับได้)		 FPR > 1%
เตือนแชทปกติบ่อยเกินไป จนผู้ใช้รำคาญและปิดระบบทิ้ง
5. Edge Latency
ความเร็วบนมือถือ		 < 300 ms
ประมวลผลเสร็จในเสี้ยววินาที ผู้ใช้รู้สึกเหมือนแชทเรียลไทม์ปกติ		 > 1000 ms
ทำให้แอปแชทกระตุก ช้า และส่งผลเสียต่อ User Experience

Q&A · เตรียมตอบคำถาม

คำถามที่คาดว่าจะถูกถาม

อะไรคือสิ่งใหม่ของงานนี้ ในเมื่อ Google ทำ Edge–Cloud แล้ว?

สถาปัตยกรรมไม่ใช่ข้อค้นพบหลักครับ สิ่งใหม่คือชุดทดสอบภาษาไทยที่วัดแคมเปญใหม่ การหลบเลี่ยง และความทันเวลาพร้อมกัน และการเปรียบเทียบแบบควบคุมบนอุปกรณ์จริงว่าความซับซ้อนแต่ละระดับคุ้มหรือไม่

เดโมที่แสดงคือระบบที่เสนอหรือเปล่า?

ไม่ใช่ครับ เดโมคือระบบฐาน S0 แบบคำสำคัญ ใช้แสดงปัญหาที่งานวิจัยต้องแก้ ได้แก่ การเตือนผิดกับข้อความปกติ การถูกหลบเลี่ยงด้วยอักขระล่องหนหรือการเปลี่ยนคำ และการเตือนช้าในบทสนทนา

ทำไมต้อง SLM?

ยังไม่ได้สรุปว่าต้องใช้ครับ นั่นคือ RQ2 ถ้า encoder ขนาดเล็กให้ผลพอและใช้ทรัพยากรน้อยกว่า ผมจะเสนอให้ใช้ encoder

ทำไมตั้งเกณฑ์ 10 จุดเปอร์เซ็นต์ / 300 ms?

เป็นเกณฑ์เริ่มต้นที่ตั้งก่อนทดลองเพื่อป้องกันการเลือกเกณฑ์ภายหลังครับ ปรับได้ครั้งเดียวหลังการศึกษานำร่อง และจะรายงานการปรับอย่างเปิดเผย

ความชุก 1% สมจริงไหม?

น่าจะสูงกว่าความจริงครับ ซึ่งยิ่งทำให้การเตือนผิดสำคัญขึ้น ผมจึงรายงาน Precision ที่ความชุกหลายระดับ ไม่ใช่ค่าเดียว (ดูแท็บ Lab)

Scamnetic ใช้ SLM บน Edge จริงหรือ?

เอกสารสาธารณะไม่ได้ยืนยันครับ Scamnetic อยู่ในงานที่เกี่ยวข้องในฐานะบริการเชิงพาณิชย์ ส่วนสถาปัตยกรรมเป็นข้อเสนอแยกของงานนี้

ตรวจพบแล้วบล็อกเลยได้ไหม?

งานนี้แยกการตรวจจับออกจากนโยบายตอบสนองครับ การระงับธุรกรรมต้องอยู่ในระบบของธนาคาร ซึ่งมีหลักฐานอื่นและช่องทางทบทวน

โมเดลบนเครื่องปลอดภัยจาก prompt injection ไหม?

ไม่รับประกันครับ ถ้าใช้โมเดลที่รับคำสั่ง จะทดสอบ prompt injection ตามกรอบ NIST AI 100-2 และโมเดลไม่มีอำนาจสั่งธุรกรรมโดยตรง

เก็บข้อมูลผิด PDPA ไหม?

เก็บบนฐานความยินยอม ลบข้อมูลระบุตัวบุคคลก่อนจัดเก็บ และผ่านคณะกรรมการจริยธรรมก่อนเริ่มครับ PDPA ไม่ได้ห้ามการส่งข้อมูลแบบเหมารวม แต่มีเงื่อนไขที่ต้องปฏิบัติตาม
